# 审稿人视角评审：UAV-LEO 任务卸载与轨迹优化论文线

> 评审日期：2026-08-10。评审对象：GDRL（uav_leo_experiment 论文线）、
> `experiments/uav_leo_v2x_paper_final` 全部结果、消融/机制分析、图集与相关代码。

## 0. 总体结论

**当前状态：不可直接投稿。** 论文的核心卖点（图强化学习 GDRL）被自己的消融实验否定：
去掉轨迹学习、去掉精确卸载，性能几乎完全不变；机制分析进一步证明 GDRL 的全部增益
来自"移动后按实际 UAV 位置精确求解卸载"这一个实现细节，与强化学习无关。
同时存在一处**致命的一致性问题**：论文参数表与实际仿真配置完全不符。
在这些问题解决前，任何中科院 2 区以上的期刊审稿都会给出 reject。

好消息：机制分析本身指向一个更诚实、更容易写扎实的故事（决策顺序的重要性 +
低复杂度联合优化），改造空间明确。

## 1. 致命问题（必须解决，否则直接拒稿）

### F1. 主结果不显著：GDRL 与 MPC-H3 几乎打平
- hard 场景：GDRL `-85.2` vs MPC-H3 `-85.6`，差异仅 `+0.4`，paired t p=0.6577、
  Wilcoxon p=0.6179 —— **完全不显著**。
- stress 场景：差异 `+2.3`，t 检验 p=0.0283 但 Wilcoxon p=0.1701 —— 也不稳健。
- 最强对手 MPC 只用了 H=3 的滚动视界。审稿人必然问：MPC-H10 / MPC-H30（近似全局最优）
  会怎样？如果 H 加长就打平或反超，论文核心结论立刻崩塌。

### F2. 消融证明"学习"没有贡献
- `GDRL - traj`（用专家轨迹替换学习轨迹）：hard `-85.215` vs 完整 `-85.202`（Δ≈0.0，p=0.30）；
  stress `-132.291` vs `-132.568`（Δ=-0.3，p=0.30）。
- `GDRL - exact offload`（去掉精确卸载）：与完整 GDRL 数值完全相同（Δ=0.0）。
- 机制表更直接：`postmove_exact`（固定算法）= GDRL 本身；`current_exact` = Predict-TEA。
- 结论：**GDRL 的收益 100% 来自"移动后精确卸载"，RL 轨迹头、图/神经网络都是冗余的。**
  任何审稿人只要看到这个消融表，就会判定方法贡献不成立。

### F3. 论文参数表与实际仿真配置不符（最危险）
- `make_paper_summary.py` 硬编码参数表：用户 CPU `5 GHz`、UAV `50/60 GHz`、
  LEO `1 PHz`、带宽 `1.0/1.1 MHz`、回传 `20 Mbps`、drop penalty `4.0`。
- 实际 `config.py`（v2x_hotspot_hard/stress）：用户 CPU `1.5 GHz`、UAV `13/15 GHz`、
  LEO `10/11 GHz`、带宽 `1.8/2.0 MHz`、回传 `7.0/6.5 Mbps`、drop penalty `6.0`。
- 即论文表格中的参数是"虚构/美化"的，与可复现代码完全矛盾；LEO `1 PHz` 也不现实。
  这是审稿人复现时最容易抓到的硬伤，性质严重（涉嫌数据不一致），必须立即修正为
  从 `make_config(...).manifest()` 自动生成的真实参数。

## 2. 重要问题（严重影响说服力）

### I1. DRL 基线表现差到可疑
- DQN/TD3/SAC/PPO/D3QN 全部 `-296 ~ -420`，远差于简单启发式 TEA（`-118`）。
- 审稿人第一反应是"基线没调好"，而不是"你的方法好"。需要：给出基线超参、
  说明动作空间（连续轨迹+离散卸载）对 DQN/TD3 的天然不利、或做一次小型超参搜索，
  否则对比无效。同理，新加的 GAT-PPO/Transformer-PPO 也应说明为何打不过纯启发式。

### I2. 能量指标自相矛盾
- GDRL energy `147.7` vs MPC `124.0`：高约 19% 能耗，换 `0.4` reward 提升，不是帕累托改进。
- 根因：`energy_weight = 0.001`，奖励几乎不惩罚能量。论文宣称"energy-efficient"，
  但奖励函数根本没在优化能量；同时表格又报告 energy，审稿人必问。
- 需要：要么把能量权重调到有意义的量级（如 0.05–0.5）并重新调参、重新训练；
  要么把能量作为硬约束（UAV 电池），并说明 reward 与能耗的关系。

### I3. 命名与方法不符
- 方法名 "GDRL"（Graph-based DRL 的遗留命名），当前实现是"残差轨迹 PPO（MLP）+
  移动后精确卸载"，没有任何图结构。论文里"graph"在哪？
- 二选一：改名（如 TEA-RL / Residual Trajectory PPO + Post-Move Exact Offloading），
  或真正引入图编码器（GAT 编码 用户-边缘拓扑）并让消融证明图结构有贡献。

### I4. 实验覆盖度不足
- 只有 2 个同族场景（hotspot-hard/stress）。缺少：
  - 规模扩展（U=8/16/32）与收敛性；
  - 非 hotspot 的随机/均匀用户分布；
  - 敏感性：deadline、带宽、energy_weight、hotspot 速度；
  - 多 UAV / 多 LEO / 用户遮挡与突发。
- 统计口径弱：40 集全部由同一 seed 派生，样本相关；应多种子（≥5）×40 集，
  报告 95% CI / effect size，主结果至少给 vs MPC 和 vs Predict-TEA 的完整统计。

### I5. 通信与物理模型简化
- 只有 path-loss exponent 3.0 的 LoS/NLoS；缺遮挡概率、多普勒、LEO 切换开销说明。
- 审稿人会要求：模型假设合理性论证 + 至少一个对信道模型参数敏感性实验。

## 4. 建议：两条可发表的改造路线

### 路线 A（推荐，改动小、省算力、诚实）
把论文主体从"图强化学习算法"改为"**决策顺序敏感的轨迹-卸载联合优化框架**"：
1. 核心贡献改为：揭示"移动前 vs 移动后"决策顺序带来可观性能差距（机制分析已支持）；
2. 提出低复杂度方法：专家轨迹 + post-move 精确卸载（当前 GDRL 实际就是这个），
   5 分钟 CPU 训练或干脆免训练；
3. 公平对比：MPC 也升级为 post-move 卸载 + H=10/30，验证差距来源不是 RL；
4. 补理论：给 post-move 卸载与（某种）最优卸载的等价/差距命题；
5. 扩展实验：多场景 + 敏感性 + 多 UAV；
6. 投稿目标：中档期刊（Ad Hoc Networks、Physical Communication、Computer Networks、
   IEEE Access、EURASIP JWCN 等）。

### 路线 B（保留"学习"卖点，需要真做算法）
让 RL 真正产生可测收益：
1. 重设奖励：energy_weight 提到有意义量级、加入电池硬约束，重新调参训练；
2. 找"学习必要"的场景：突发/不可预测需求、遮挡、紧电池预算、LEO 切换——
   在这些场景下专家轨迹明显次优，学习才有空间；
3. 引入真图编码器（GAT/Transformer 编码用户-边缘拓扑），并用图结构消融证明贡献；
4. 基线也统一用 post-move 精确卸载，隔离"学习只负责轨迹"；
5. 多种子统计 + 更丰富场景。
   （这条路工作量大，但才撑得起"Graph-based DRL"的标题。）
