> 日期：2026-09-07  
> 相对：`disaster_va_dag_ho/` 现有实现与主表 v1（N=30 软连接、MAPPO 学飞）  
> 目标：环境变难；正文**不再**以「学轨迹」为主创新；主方法改为固定轨迹 + 可见窗感知 DAG 嵌入调度。

## 0. 创新点改写（论文贡献 · 锁定）

### 新主贡献（写进摘要/贡献段）

1. **硬覆盖与间歇可见并存下的依赖任务嵌入调度**  
   终端仅在 UAV 覆盖半径内可接入；覆盖外不能经 UAV 中继。在 DAG 拓扑序 + LEO 可见窗约束下，用嵌入式启发式（ScheduleDAG）做节点放置：`{UAV, Relay-LEO, wait}`（可选后续加 Direct-LEO）。

2. **可见窗剪枝的可行性机制**  
   决策期禁止无法在窗内完成的 LEO 放置；相对「常在线假设 / 无剪枝」在相近或更高完成率下降低时延与无效跨窗占用。

3. **（结构对照，非轨迹学习）分层优于扁平**  
   同固定轨迹下，嵌入调度显著优于端到端扁平 RL 学卸载（原 B4/B5 口径保留为卸载-only）。

### 明确删除 / 降级

| 原表述 | v2 |
|--------|-----|
| MAPPO 学 UAV 轨迹为主贡献 | **删除**；轨迹用固定策略 |
| 「联合轨迹与卸载的学习」 | **禁止**作为创新点 |
| 与 PMEO「先飞后卸」、LAETS 同步 | 仍刻意错开，不写 |

### 一句话新故事

> 灾后多 UAV 硬覆盖接入 + LEO 可见窗回传；救援应用为 DAG。本文不学习飞行轨迹，而提出覆盖感知、可见窗感知的依赖任务嵌入调度，证明其优于无窗剪枝与扁平 RL 卸载。

## 1. 环境加难（必须实现）

### 1.1 规模

| 项 | v1 | v2（主表） |
|----|----|------------|
| 终端 \(N\) | 30 | **40** |
| UAV \(K\) | 3 | **3** |
| LEO \(L\) | 2 | 2（交错窗保留） |
| \(T\) | 50 | 50 |

每机关联上限改为 \(\lceil N/K\rceil\)（约 14），但**先受硬覆盖过滤**。

### 1.2 硬覆盖（核心）

- 配置项：`uav_cover_radius_m`（初值建议 **500**；若 hover 成功率仍 >0.80 再降到 400；若 <0.45 再升到 600）。
- 时刻 \(t\)：终端 \(n\) 可被 UAV \(k\) 服务，当且仅当水平距离 \(\|\mathbf{x}_n-\mathbf{p}_k\| \le R\)。
- 关联：只在覆盖内的 \((n,k)\) 上按速率贪心 + 每机容量上限；**允许 `assignment[n]=-1`（本时隙连不上）**。
- 覆盖外：\(r_{n,k}=0\)（或直接不进入候选）；不能注册/推进需经该 UAV 上行的卸载。

### 1.3 连不上时任务规则（写死一种）

**采用 A（推荐）：**

- 无关联且应用仍 pending：本时隙不能向 UAV/中继 LEO 放置新节点。  
- 已 pin 到某 UAV、但终端走出该机覆盖：上行中的源数据不可继续；该应用若截止期内无法回到覆盖 → **失败**（计 \(F\)）。  
- 指标增加：`frac_unassociated`（每时隙无关联终端比例均值）、`fail_uncovered`（因覆盖导致的失败数，可与总失败分开或打标签）。

### 1.4 热点到达（强烈建议，与硬覆盖同开）

- 在地图上设 \(M=2\) 个慢移热点中心（或固定救援点）。  
- 热点半径内 \(\lambda=\lambda_{\mathrm{high}}\)，热点外 \(\lambda=\lambda_{\mathrm{low}}\)（可复用现有高低 λ，但改为**空间非齐次**，不再全图同一 λ）。  
- 突发时间窗 \([15,35]\) 可保留为「全局乘子」或只加强热点。

### 1.5 轨迹（不学）

主方法与 B1–B3 **共用「非学习轨迹」**，主表固定一种默认：

| ID | 轨迹 | 主表角色 |
|----|------|----------|
| T-hover | 悬停在初始均匀位置 | 弱基线 |
| T-sweep | 分区慢扫掠 | 可选 |
| **T-patrol（推荐作本文默认轨迹）** | 各 UAV 负责一条走廊条带，在条带内来回巡逻 | **本文 + B6 使用** |
| T-chase | 追责任区/热点积压质心（规则） | 强启发式对照 |

**本文算法不输出速度**；`env.step` 的 UAV 动作由上述规则轨迹模块给出。

MAPPO 轨迹代码保留在仓库，**主表不跑**；附录可一行「学飞 vs 固定巡逻」可选，非正文必须。

## 2. 主方法 v2 定义

**名称：** VA-DAG-HO（v2）= **T-patrol + 硬覆盖关联 + ScheduleDAG（VW-prune + DAG-order）**

时隙顺序：

```
到达(空间非齐次) → 规则轨迹移动 → 硬覆盖过滤 + 规则关联
  → ScheduleDAG → 结算成功/失败/能耗 → 指标
```

下层候选仍：`UAV_k`（pin）、窗内 `LEO`；**本轮可不做 Direct-LEO**（列入「可选 W+」）。

## 3. 对比与消融（主表须重跑）

### 3.1 主表方法

| ID | 内容 |
|----|------|
| B1-random | 随机走 + 同调度器 + 硬覆盖 |
| B2-chase | 追积压 + 同调度器 |
| B3-hover | 悬停 + 同调度器 |
| **Ours** | T-patrol + 同调度器 + VW-prune |
| B4-flat | T-patrol 固定 + 扁平 RL **只学卸载**（不学飞） |
| B5-SACflat | 同上，off-policy 扁平卸载 |
| B6-noVWprune | T-patrol + 调度但无决策期窗剪枝 |

### 3.2 消融

- w/o VW-prune（=B6）  
- w/o DAG-order  
- w/o hard-cover（软连接对照，证明硬覆盖改变问题）——**建议加，很有说服力**  
- w/o embed（=B4）

### 3.3 验收数字（调 \(R\) / λ 直到满足）

在 seeds 0–4 上：

1. **B3-hover 成功率 ∈ [0.55, 0.75]**（中心目标 ~0.65）  
2. **Ours 成功率比 hover 至少 +0.05，或时延低 ≥10%**（至少一个主指标显著）  
3. **Ours vs B4/B5：成功率差距 ≥0.10**（保持嵌入优势）  
4. **平均 `frac_unassociated` ∈ [0.15, 0.40]**（确实存在连不上，又不是全图瘫痪）  
5. B6 时延劣于 Ours（成功率可接近）

调参顺序：先定 \(R\) 使 (1)(4) 满足 → 再微调截止期/DAG scale → 再跑满主表。
