# VA-DAG-HO 后续优化修改计划（编辑部修订路线图 v0.1）

> 依据 2026-09-09 编辑部意见整理。目标：先解决**结构性风险**，再补**统计与稳健性**，最后重构叙事。
> 若某一闸门未过，按对应预案改写声明或换主线，不允许"微调数字后照投"。

---

## 0. 总路线与决策闸门

| 阶段 | 内容 | 决策闸门 |
|---|---|---|
| P0 基线公平化（约 3-5 人·天） | hover-at-hotspot、信息对等 chase、文献基线 | 决定头条声明是否保留"巡逻 vs hover" |
| P1 几何稳健性（约 2-3 人·天） | 热点布局扫描 | hover 差距是否依赖"热点在车道内" |
| P2 机制因果（约 2-4 人·天） | LEO 队列占用归因、能耗约束生效、未关联分解 | C2"剪枝=时延机制"能否从相关升级为因果 |
| P3 统计重建（约 3-5 人·天） | n 扩展、多训练 seed、CI、多重比较、p 下界标注 | 头条 Δ 是否带 CI 仍显著 |
| P4 外推网格（约 3-6 人·天） | 可见周期/截止期/容量/热点布局 | 结论成立区间能否被界定 |
| P5 论文重写（约 3-5 人·天） | 新声明表、重写引言/机制/局限 | 达成"可送审"版本 |

**总闸门（投递决策）：**
- 通过 P0–P5 → 冲 TVT/TWC 或 IEEE IoT-J 主刊；
- P0/P1 出现红线（见 §1 预案）→ 换主线后仍走 P2–P5；
- P3 显示 RL 加预算后追平嵌入 → 放弃 "embedding vs RL" 头号声明，改为搜索/最优性对照；
- 时间不允许时（硕士/首投）：P0+P1+P3 中心格 + P5 为必做，P2/P4 可精简。

## 1. P0 基线公平化（结构性风险，最先做）

### 1.1 E1 hover-at-hotspot（新基线 B7）
- 做法：`configs/` 新增 hover 站位配置。3 架无人机不再均匀固定，而是按热点负载质心分配站位（2 架各占一热点中心 + 1 架居中或按当前到达率加权），轨迹仍固定、不学习。
- 位置：`disaster_va_dag_ho/baselines/` 或复用现有 hover 运动器加站位参数；评估复用 `run_table.py` / `run_sens_v2.py` 框架。
- 数据：R=800、λ_high=0.2，scene seeds 0–9（先 5 后扩 10），输出与主表相同的指标集（成功率、条件/有效时延、能耗、无效 LEO、未关联比例）。
- 验收/判读：
  - 若 Ours−B7 ≈ Ours−B3（巡逻优势保持）→ 保留 patrol 叙事，B7 进主表；
  - 若 Ours−B7 减半或归零 → **红线预案 A**：头条对比基线改为 B7 或"覆盖感知关联+调度"；删去"轨迹为该几何设计"的因果性表述。

### 1.2 E2 信息对等（chase 的信息量扫描）
- 质疑：chase 用全知当前积压，公平性不足；反之 patrol 完全无信息。
- 做法：给 chase 加信息刷新周期 τ∈{1（现状）, 5, 10, ∞}（∞=巡逻级无信息或随机指向），同调度器下测成功率/时延。
- 另一侧：给 patrol 一个"慢速热点估计"选项（每 5–10 s 更新一次站位，仍非学习），看信息量对称后差距如何变化。
- 验收/判读：
  - 画"成功率 vs 轨迹信息量"曲线；若嵌入收益只在低信息区出现，把 C3 改为**信息受限下的结构收益**声明（这是比"我们赢 RL"更站得住的科学结论）；
  - 若 chase 在全信息区全面占优（现状已部分如此），讨论段如实承认，不再用"巡逻不需要先验"一句话带过——需给侦查阶段的信息假设一个定量理由（如无定位/无积压上报）。

### 1.3 E3 文献基线（外部锚点，至少 2 个）
- 同一仿真实现两个可引用的外部调度器并跑 5 seeds：
  1. 窗口感知 EDF/list scheduling（可视为去掉你的紧迫度启发式与贪心排序的最简对照，用于证明你的优先级规则有增量）；
  2. 一篇已发表的 UAV-LEO 卸载/调度方法改造版（如"常在线 LEO + 软连接"式的对比实现 [6]-[8] 类），在**本场景规则下**公平运行。
- 若时间有限，最低限度是 1+第 2 项用"无窗剪枝+EDF"代替，但在论文 Limitations 中注明未与文献实现直接对齐的风险。
- 交付：新增一行或一个小表"外部锚点 vs Ours"，作为审稿人"只比内部基线"质疑的正面回答。

## 2. P1 几何稳健性（防"自证循环"）

### 2.1 E4 热点布局扫描
- 变体（其余全冻结，R=800、λ_high=0.2、各 5 seeds）：
  1. 现状：两热点在上下条带内（对齐）；
  2. 错位：两热点移到巡逻车道边界/相邻条带交界；
  3. 边界：热点一半在车道覆盖内、一半在外；
  4. 随机：热点中心由固定 layout seed 随机抽取（report 2-3 个 layout seed）。
- 只跑确定性行 + hover + B7（若已实现）+ B4（可选，先 hover/B7）。
- 验收/判读：
  - 列"每布局下 Ours−hover、Ours−B7 的 Δ（5 seeds 均值与符号一致性）"；
  - 若 ≥2 个非对齐布局下差距消失或反转 → 把结论改写成带条件边界（"当任务集中在巡逻覆盖条带内时…"），并加一张"几何条件×差距"图；
  - 若全部保持 → 在正文写"结论对热点与车道相对位置稳健"，并放附录。

## 3. P2 机制因果（把相关升级为因果）

### 3.1 E5 剪枝因果归因
- 质疑：745 vs 264 次无效 LEO 尝试只是相关性。
- 做法：在 env/调度器里加逐 slot 日志：
  - LEO 中继队列长度（B6 与 Ours 对齐记录）；
  - 无效提交发生后的 1–2 个 slot 内，其他应用完成是否被推迟；
  - 对每个完成应用记录"若非其前若干无效提交占用资源，预计完成时刻"（反事实估计用重放：把 B6 的无效提交从执行轨迹中移除后重放，比较完成时延）。
- 交付：
  - Δdelay 中可由"无效提交后的队列占用"解释的比例；
  - 若 <50%，承认剪枝的时延收益部分来自其他路径（如调度顺序变化），并把 C2 措辞降级为"与无效提交关联的时延收益"。
- 复现注意：所有反事实重放与主表使用同一批 frozen CSV 的 scene/train seed，并记入 `run_log.csv`。

### 3.2 E6 未关联分解
- 做法：统计并报告每方法每 slot 的未关联终端中：(a) 因无 UAV 在其 R 内（coverage-unreachable）vs (b) 因容量上限被挤出（capacity-blocked）。
- 现状旁证：`ablation` 中"w/o hard cover"未关联比例≈0，暗示当前负载下容量不紧；若数据证实，把正文"约 25% 未关联证明覆盖约束生效"改为"未关联几乎全部由覆盖造成（容量挤出 <x%）"，消除混淆。

### 3.3 E7 能耗约束是否生效
- 做法：
  1. 跑 200 s 水平线（或连续多 episode），报告各 UAV 期末电池余量分布；
  2. 补一个"低电量策略生效"变体（20% 阈值降速/节流），看能量是否进入决策回路；
- 交付：正文 Metrics/能量段改写为——"本水平线下电池未耗尽，能耗作为资源消耗维度报告，不作为优化目标"（若数据支持），或补能量受限变体实验。

## 4. P3 统计重建

### 4.1 E8 主张族与样本
- 冻结"头条主张族"（pre-register 在 REVISION 文档里，防止事后挑选）：
  - 主：中心格 n=20，配对检验仅 8 个：Ours vs {hover, B4, B6, chase} × {success, eff-latency}，方向预先指定；
  - 检验全部改为**配对差分的 bootstrap 95% CI + Wilcoxon p**，两者并列报；
  - p 报告注明离散下界：n=5 时单边最小 p=0.0312，n=10 时最小 p≈0.00098（报 p=0.0010 时加脚注"接近 n=10 可达最小值"）；
  - 多重比较：主族用 Holm 校正；敏感性/规模网格标注"未校正，仅看方向一致性"。
- 数据：新增 `v2_stats_n20_raw.csv`（scene seeds 0–19）——Ours/hover/B4/B6/chase 确定性行一次跑完；B4 的 RL 行按配对的 train seed 重训。

### 4.2 E9 RL 训练方差
- 做法：B4 在中心格用 3 个训练 seed/场景 seed 重训（或至少 3 个独立训练 seed），报告 Δ(Ours−B4) 的跨训练 seed 分布；若可行，预算曲线延到 2000 ep 看是否追平（回应"没训够"）。
- 红线：若 2000 ep 的 B4 追平 Ours → 启动 §0 预案 C（RL 声明降级/移除）。
- 交付：一张"训练预算×成功率"图（含多训练 seed 包络）+ 一段诚实判读。

## 5. P4 外推网格（界定成立区间）

### 5.1 E10 参数扫描（方法×格 均 5 seeds，全部其余冻结）
| 维度 | 取值 | 理由 |
|---|---|---|
| 可见周期/占空比 | (22 s, 0.4) 基准；(15 s, 0.35)；(30 s, 0.45) | 剪枝价值的核心依赖 |
| 截止期 | 8 / 12 / 20 s | 有效时延与成功率定义依赖它 |
| 卫星容量 | 5 / 10 / 20 Mb/s | 中继争用程度 |
| 热点布局 | 见 E4 | 几何依赖 |
- 方法集：Ours、hover、B7、B4（B6 只在中心做），保证成本可控。
- 验收：预先写"声明成立判据"（如 Ours−hover≥+0.05 且 Ours−B4≥+0.05 在 ≥75% 格内成立），结果以"成立区间图/表"呈现，不事后挑格子。

## 6. P5 论文重写（叙事结构）

按以下顺序改，不要先调文字：
1. **新声明表**：把每个段落声明映射到"方法×数据文件×检验"，删除无对应证据的句子；
2. **重写引言**：先给"既有模型在硬覆盖+间歇可见下的具体失效环节"（引用补全后的 [1]-[15]），再给本文问题，最后给三条可证伪声明（对应 C1-C3 的修订版）；
3. **方法**：补形式化模型（场景/目标/约束定义）、复杂度分析（哪怕 NP-hard 的论证或启发式复杂度的上界）、DAG 模板参数、能量/信道系数、RL 状态动作奖励的完整定义；
4. **机制段**：用 E5/E6/E7 的产物替换现在基于相关性的论述；"physically meaningful / truthful" 类修辞全部删除；
5. **新增 Limitations 小节**：信息假设、几何依赖、单小区、无云/无直连、参数扫描边界——主动写，不给审稿人当攻击点；
6. 附一个"可复现附录"：config hash、seeds、命令、CSV 命名约定（复用现有 `run_log.csv` 机制）。

## 7. 执行顺序与工作量（最小可行版）

若目标为"能投出去的一版"（IoT-J/中等会议），顺序为：
1. E1+B7（决定叙事） → 2. E4（几何） → 3. E6+E7（便宜且消混淆）
4. E8 中心格 n=20 + CI（统计底线） → 5. E3 最少 1 个文献锚点 → 6. P5 重写。
预计 **8–12 人·天**。

冲 TVT/TWC 再加：E2（信息曲线）、E5（因果归因）、E10（外推网格）、E9（RL 预算/训练方差）。预计再加 **8–15 人·天**。

## 8. 红线预案汇总（提前想好，避免被动）

- **红线 A**（E1 未过）：撤 patrol-vs-hover 叙事，B7 转正为弱基线，头条改"关联+调度嵌入在硬覆盖下的收益"。
- **红线 B**（E4 未过）：所有头条差距加"热点与巡逻车道对齐时"限定词；如审稿压力大，把论文定位为"条件地图"研究而非方法优越性研究。
- **红线 C**（E9 未过）：放弃 RL 对照作为头条，改为与 E3 外部锚点 + 搜索/最优性（小规模 MILP/CP gap）对照；RL 移入附录或删除。
- 红线预案不是失败，而是防止把"一个假设条件下的工程评估"硬说成"普适结构结论"。
