> 老师，主线不是继续刷 GDRL。场景是车辆–UAV–LEO 三层热点车联网；核心是证明卸载必须在 UAV **移动后位置**求值，并给出免训练方法 PMEO / 多机 Eco，以及数字孪生下的负载触发同步 LAETS。对比上相对主流 DRL 明显更好，多机还能打过短视界 MPC。下面按：场景建模 → 方法 → 多机结果 → 机制与单机 → LAETS → 计划。

# 第 1 段｜系统结构怎么介绍（约 2 分钟）

## 1.1 对着图讲结构（开口稿）

![系统架构](../experiments/uav_leo_v2x_paper_final/figures/architecture.png)

> 请看这张系统图。底层是道路上的车辆用户，沿着路网移动；粉色区域是**移动热点**——模拟拥堵或事故区，热点附近任务到达概率接近 1，热点外仍有稀疏到达。中间是 UAV：既是边缘算力节点，也是上卫星的中继。上层是 LEO。  
> 每个任务三条路：本地算、卸到 UAV、或经 UAV 回传到 LEO。  
> 关键动态有两层：第一，**热点每个时隙都在路上移动**（约 18–20 m/s），所以任务空间分布每秒都变；第二，UAV 自己也飞，飞到哪用户—UAV 信道就变。因此每个时隙约 1 秒都要联合决定：UAV 的二维位移，以及每个用户的卸载目标与比例。

## 1.2 热点是否每个时隙都变？

**是。** 环境每时隙更新热点位置与速度，再做一步预测。

**字母公式：**

$$\hat{\mathbf{h}}_{t+1}=\mathbf{h}_t+\mathbf{v}^{\mathrm{hot}}_t\Delta t$$

**中文公式：**

> 预测的下一拍热点位置 ＝ 当前热点位置 ＋ 热点速度 × 一个时隙时长

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $\mathbf{h}_t$ | 第 $t$ 个时隙的热点平面位置（二维坐标） |
| $\mathbf{v}^{\mathrm{hot}}_t$ | 热点速度向量（道路方向 × 有符号速率，约 18–20 m/s） |
| $\Delta t$ | 时隙长度，主实验 $=1$ 秒 |
| $\hat{\mathbf{h}}_{t+1}$ | 对「下一时隙热点会在哪」的预测（帽子表示预测值） |

不是整局固定一个热点中心；速度来自仿真道路运动观测，不是神经网络估出来的。

## 1.3 决策是「上下左右」吗？

**不是。** 是二维连续位移，再限速、再更新位置。

**字母公式：**

$$\mathbf{m}_t\in\mathbb{R}^2,\quad \|\mathbf{m}_t\|\le v_{\max}$$

$$\mathbf{p}_t=\mathrm{clip}\big(\mathbf{p}_{t-1}+\mathbf{m}_t\Delta t\big)$$

**中文公式：**

> 本时隙飞行指令 ＝ 平面上的一个二维位移向量，长度不能超过最大速度  
> 新位置 ＝ 把（旧位置 ＋ 位移×时隙时长）裁剪回地图范围内

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $\mathbf{m}_t$ | 第 $t$ 时隙 UAV 的位移/速度指令（不是上/下/左/右四键） |
| $v_{\max}$ | UAV 最大速度上限 |
| $\|\mathbf{m}_t\|$ | 位移向量的长度（飞多远） |
| $\mathbf{p}_{t-1}$ | 移动前 UAV 水平位置 |
| $\mathbf{p}_t$ | 移动后 UAV 水平位置 |
| $\mathrm{clip}(\cdot)$ | 防止飞出仿真区域的裁剪 |

卸载动作另算：离散「目标 × 比例网格」。

## 1.4 车—UAV 连接与「出覆盖还上卫星」

> 我们没有硬覆盖圆（超过 $R$ 米就断）。用 LoS/NLoS + 香农速率：离得越远速率越差。

**字母公式：**

$$r_{u\to\mathrm{LEO}}=\min\big(r_{u,k^{\star}},\,r_{k^{\star},\ell}\big)$$

**中文公式：**

> 用户经 UAV 上卫星的有效速率 ＝ min（用户到该 UAV 的无线速率，该 UAV 到卫星的回传速率）

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $r_{u,k}$ | 用户 $u$ 到第 $k$ 架 UAV 的可达速率（随距离变） |
| $r_{k,\ell}$ | UAV $k$ 到 LEO $\ell$ 的回传速率（主实验常取约 20 Mbps 容量） |
| $k^{\star}$ | 使中继路径最好的那架 UAV |
| $\min$ | 两跳里慢的那一跳卡脖子 |

若用户远离所有 UAV，第一跳 $r_{u,k}$ 很差 → 枚举会偏向本地或超时丢弃；不会「人已飞出覆盖还免费走卫星」。

## 1.5 统一标尺（Reward 公式 · 必报）

### （1）时隙奖励

**字母公式：**

$$
R_t = -\,w_L\sum_u T_{u,t} - w_e\Big(\sum_u E^{\mathrm{task}}_{u,t}+\sum_k E^{\mathrm{fly}}_{k,t}\Big) - \lambda\sum_u D_{u,t}
$$

**中文公式：**

> 本时隙奖励 ＝ −（时延权重 × 所有用户时延之和）−（能量权重 ×（所有任务能耗 ＋ 所有 UAV 飞行能耗））−（丢弃惩罚 × 丢弃个数）

**中文解释：**

| 符号 | 中文含义 | 典型取值 |
|---|---|---|
| $R_t$ | 第 $t$ 时隙的 reward（越大越好，因为前面有负号） | — |
| $w_L$ | 时延权重 | $1$ |
| $T_{u,t}$ | 用户 $u$ 在时隙 $t$ 的端到端时延（秒） | — |
| $\sum_u T_{u,t}$ | 本时隙所有用户时延加总 | — |
| $w_e$ | 能耗权重 | $0.001$ |
| $E^{\mathrm{task}}_{u,t}$ | 用户 $u$ 本时隙任务相关能耗（本地算 + 发射等） | — |
| $E^{\mathrm{fly}}_{k,t}$ | 第 $k$ 架 UAV 本时隙飞行能耗 | — |
| $\lambda$ | 超时丢弃的惩罚系数 | $4$ |
| $D_{u,t}$ | 是否丢弃：超时为 $1$，否则为 $0$ | 0/1 |

默认 $w_L=1,\;w_e=0.001,\;\lambda=4$。所有基线与 PMEO **同一环境、同一 $R_t$**。  
时延大 / 飞得费电 / 超时变多 → $R_t$ 更负（更差）。

### （2）单用户时延骨架

**字母公式：**

$$T_u=\max\big(T^{\mathrm{loc}},\,T^{\mathrm{tx}}+T^{\mathrm{wait}}+T^{\mathrm{svc}}\big)$$

**中文公式：**

> 用户时延 ＝ max（本地计算那一部分的时间， 传输时间＋排队等待＋远端计算时间）

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $T^{\mathrm{loc}}$ | 留在车上本地算的那部分时间 |
| $T^{\mathrm{tx}}$ | 把卸载部分传到 UAV/经 UAV 上星的传输时间 |
| $T^{\mathrm{wait}}$ | 在 UAV 或 LEO 共享队列里排队等待的时间 |
| $T^{\mathrm{svc}}$ | 在 UAV 或 LEO 上真正算完的时间 |
| $\max$ | 本地与远端并行时，总时延取较慢的一边 |

全本地时则直接 $T_u=$ 全部 cycles / 车载算力。若 $T_u>$ 截止时延 $T_{\mathrm{ddl}}$，则 $D_u=1$。

### （3）飞行能耗

**字母公式：**

$$E^{\mathrm{fly}}=P_{\mathrm{hover}}\Delta t + c_{\mathrm{drag}}v^3\Delta t$$

**中文公式：**

> 飞行能耗 ＝ 悬停功率×时隙时长 ＋ 阻力系数×（速度的三次方）×时隙时长

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $P_{\mathrm{hover}}$ | 悬停功率（即使几乎不飞也有底噪功耗） |
| $c_{\mathrm{drag}}$ | 与空气阻力相关的系数 |
| $v$ | 本时隙平均飞行速率 $=\|\mathbf{p}_t-\mathbf{p}_{t-1}\|/\Delta t$ |
| $v^3$ | 飞得越快，阻力项涨得很快 |

# 第 2 段｜PMEO 全流程（约 2.5 分钟）

![PMEO 中文流程](../experiments/uav_leo_v2x_paper_final/figures/fig_ch3_pmeo_pipeline_cn.png)

## 2.0 开口总起

> PMEO 每个时隙四步：观测 → 启发式定轨迹 → 在新位置精确枚举卸载 → 执行。零训练。创新在步骤三必须用移动后位置 $\mathbf{p}_t$。

## 阶段 ① 观测（这些字母是什么）

**字母写法：**

$$\{\mathbf{x}_{u,t},\,b_{u,t},\,\kappa_{u,t}\},\quad \mathbf{h}_t,\,\mathbf{v}^{\mathrm{hot}}_t,\quad \mathbf{p}_{t-1},\quad Q^{\mathrm{uav}},\,Q^{\mathrm{leo}}$$

**中文写法：**

> 观测包括：每个用户的位置、任务比特数、每比特算力周期；热点位置与热点速度；UAV 移动前位置；UAV/卫星上的计算排队量

**中文解释（逐个字母）：**

| 符号 | 中文含义 |
|---|---|
| $\mathbf{x}_{u,t}$ | 用户 $u$ 在时隙 $t$ 的平面位置坐标 |
| $b_{u,t}$ | 该用户本时隙任务的数据量（比特）；无任务则为 0 |
| $\kappa_{u,t}$ | 每比特需要多少 CPU cycles（计算密度） |
| $b_{u,t}\kappa_{u,t}$ | 该任务总计算量（后面质心权重就用它） |
| $\mathbf{h}_t$ | 热点当前位置 |
| $\mathbf{v}^{\mathrm{hot}}_t$ | 热点当前速度（用于预测下一拍） |
| $\mathbf{p}_{t-1}$ | UAV 在本时隙**起飞前**的位置 |
| $Q^{\mathrm{uav}},Q^{\mathrm{leo}}$ | UAV / LEO 计算队列 backlog（已堆积未算完的 cycles） |

## 阶段 ② 启发式轨迹

### 2.1 任务加权质心

**字母公式：**

$$w_{u,t}=b_{u,t}\kappa_{u,t},\qquad
\mathbf{c}_t=\frac{\sum_u w_{u,t}\,\mathbf{x}_{u,t}}{\sum_u w_{u,t}}$$

**中文公式：**

> 用户权重 ＝ 任务比特 × 每比特周期（＝总计算量）  
> 任务质心 ＝（各用户位置 × 各自权重）的加权平均

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $w_{u,t}$ | 用户 $u$ 的负载权重 |
| $\mathbf{c}_t$ | 本时隙「活最多」的空间中心（质心） |
| 分母 $\sum w$ | 归一化，保证是加权平均 |

无任务时退化为用户位置简单平均。直觉：算得多的用户把质心往自己那边拉。

### 2.2 预测热点（同上 1.2，再念一遍）

**字母公式：** $\hat{\mathbf{h}}_{t+1}=\mathbf{h}_t+\mathbf{v}^{\mathrm{hot}}_t\Delta t$  
**中文公式：** 预测热点 ＝ 当前位置 ＋ 速度×1 秒  
**速度从哪来：** 仿真器道路运动写入观测；不是神经网络。

### 2.3 混合目标与一步飞行

**字母公式：**

$$
\mathbf{g}_t=0.5\,\mathbf{c}_t+0.5\,\hat{\mathbf{h}}_{t+1}
$$

$$
\mathbf{m}_t=\mathrm{clip}_{v_{\max}}(\mathbf{g}_t-\mathbf{p}_{t-1})
$$

$$
\mathbf{p}_t=\mathrm{clip}_{\mathrm{area}}(\mathbf{p}_{t-1}+\mathbf{m}_t\Delta t)
$$

**中文公式：**

> 飞行目标点 ＝ 0.5×任务质心 ＋ 0.5×预测热点  
> 飞行指令 ＝ 朝目标点的方向，但一步位移不超过最大速度  
> 新位置 ＝ 旧位置沿指令飞完后，裁剪回地图内

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $\mathbf{g}_t$ | 本时隙理想目标点（混合） |
| $0.5/0.5$ | 一半看当前任务在哪，一半看热点下一拍漂到哪 |
| $\mathrm{clip}_{v_{\max}}$ | 限速：一步飞不到目标就先飞一段 |
| $\mathbf{p}_t$ | **飞完后的真实位置**（后面卸载必须用它） |

一步未必到 $\mathbf{g}_t$；每个时隙都重算（质心和热点都在变）。

## 阶段 ③ 移动后精确卸载

在 $\mathbf{p}_t$ 上重算信道速率后，对每个活跃用户枚举约 15 格。

**字母公式：**

$$c_u=T_u+w_e E_u+\lambda D_u$$

$$\text{选使 }c_u\text{ 最小的 }(a_u,\rho_u)$$

**中文公式：**

> 用户个人代价 ＝ 时延 ＋ 能量权重×该用户任务能耗 ＋ 丢弃惩罚×是否丢弃  
> 在「本地 / UAV / LEO」×「比例 0,0.25,0.5,0.75,1」里选代价最小的组合

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $c_u$ | 用户 $u$ 的个人代价（与全局 $R_t$ 同一套权重） |
| $a_u$ | 卸载目标：本地 / UAV / LEO |
| $\rho_u$ | 卸载比例：多大比例的任务丢到边缘 |
| 关键 | 必须用 $\mathbf{p}_t$ 算速率，不能用 $\mathbf{p}_{t-1}$ |

## 阶段 ④ 执行并得到 $R_t$

环境执行移动与卸载，按 1.5 节公式结算本时隙奖励。

## 多机一句

> 多机：先按速率+容量关联用户到各 UAV；每机对自己的关联用户算质心，再与最近热点预测混合；Eco 再在「原地/专家飞/半速/纯质心…」候选上短视界打分，加上飞行能耗。

## 本段追问

- **要 GNN 吗？** 主方法不用。  
- **为何权重用 $b\kappa$？** 对齐真实计算负载，比纯几何中心更贴「哪有活」。

# 第 3 段｜多机主结果：逐图讲清（约 2.5 分钟）★

## 3.1 统一标尺与对比算法

所有方法同一环境、同一 $R_t$（见 1.5）。别人算法接入方式：同一仿真器重实现/接接口后评估。

| 类别 | 代表 | 怎么接到本环境 |
|---|---|---|
| 本文 | PMEO-M / **PMEO-M-Eco** | 关联 + post-move 枚举；Eco 加候选短前瞻 |
| 顺序消融 | Current-exact-M | 同轨迹，卸载用移动前位置 |
| 免训练强基线 | MPC-M-H3 | 多机短视界滚动优化，代价同一套 |
| 多机 DRL | DQN / TD3 / SAC | 各机学策略，同环境评估 |
| 单机另表 | PPO、GAT-PPO、Transformer-PPO、P-D3QN、GDRL… | 同 $R_t$ 评估 |

## 3.2 图：多机四指标

![k3 四指标](../experiments/uav_leo_v2x_paper_final/figures/fig1_k3_comparison.png)

**图什么意思：** $K=3$ 架 UAV、约 51 用户；(a) reward (b) 成功率 (c) 时延 (d) 能耗。  
**谁的好：** 红色 PMEO-M-Eco 最好或并列最好。  
**原因：** 顺序正确 + Eco 省电飞 + DRL 难训 + 多机 MPC 未必更优。  
**消融：** 去均衡关联 / 收窄候选会掉点；能量权重扫描 Eco 仍站得住。

> 开口：主战场。免训练 Eco 压过要训练的多机 DRL，也压过短视界 MPC。

## 3.3 图：规模扫描

横轴换规模，纵轴 reward；多数点红（Eco）在蓝（MPC）上。区域极大时差距缩小——诚实边界。

## 3.4 算力账

Eco ≈ 11 ms/时隙；MPC-M-H3 ≈ 17 ms；DRL 另计数万步训练。

## 5.1 定时刷新权衡

![τ 权衡](../digital_twin_uav_leo/results/fig_combined_k3_tau.png)

| 符号 | 中文 |
|---|---|
| $\tau$ | 每隔多少个时隙做一次全量孪生同步；越大刷得越稀 |

$\tau$ 从 1→10，reward 掉很多 → 状态一旧，顺序优势被淹没。

## 5.2 LAETS vs 定时前沿

![自适应](../digital_twin_uav_leo/results/fig_combined_k3_adaptive.png)

**字母公式（触发条件直觉）：**

$$\mathrm{err}\propto\frac{\lvert\mathrm{Load}_{twin}-\mathrm{Load}_{phys}\rvert}{\mathrm{Load}_{\mathrm{ref}}},\quad \text{若 }\mathrm{err}>\delta\text{ 则同步}$$

**中文公式：**

> 误差 roughly＝｜孪生总负载 − 物理总负载｜／参考负载；误差大于阈值 $\delta$ 就全量同步

**中文解释：**

| 符号 | 中文含义 |
|---|---|
| $\mathrm{Load}_{twin}$ | 孪生副本里估计的聚合任务量 |
| $\mathrm{Load}_{phys}$ | 物理世界真实聚合任务量 |
| $\delta$ | 触发阈值 |
| 蓝点 | 不同 $\tau$ 的定时刷新 |
| 红点 | LAETS；应落在蓝线上方/左上（更少同步、更好或相当） |
| 黄三角 | 逐用户触发（太敏感，同步太多） |

## 5.3 时机图

![时机](../digital_twin_uav_leo/results/fig_sync_timing_burst.png)

粉区＝突发；红三角＝同步时刻，多在突发起止 → 「负载变了才刷」，不是均匀撒胡椒面。

> 串讲：定时 $\tau$ 一大就崩 → LAETS 用更少同步打过或追上定时前沿 → 时机图证明刷在突发边界。

# 第 6 段｜站位、进度、请拍板（约 1 分钟）
